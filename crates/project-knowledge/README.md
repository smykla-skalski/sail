# Reviewed project knowledge core

This crate prepares a proposed edit from one selected private memory. It has no app command or automatic trigger. The caller must load the selected record from Sail's private memory store by ID and derive repository write access from a trusted source; neither value may come from a browser request alone.

The caller supplies the destination and proposed text explicitly. Preview reads an existing tracked root instruction file or `docs/*.md`, returns the original memory and source session, and shows the exact replacement diff without writing. It rejects destinations whose working bytes differ from the tracked Git blob, including CRLF checkouts, NUL bytes, proposed carriage returns, active Git `filter`, `ident`, or `working-tree-encoding` attributes, and Git `diff` overrides that hide or transform the reviewed text. Acceptance repeats those checks before creating an artifact. Rejecting a preview only discards it. Acceptance checks write access, `HEAD`, the destination path, and the original bytes again, then prepares an uncommitted Git tree in a private temporary bare Git artifact. The artifact reads existing source objects through alternates but writes its new blob, tree, and `refs/sail/knowledge/*` ref only inside the artifact. The result returns the base revision, artifact path, ref, and a linked worktree path. `PreparedChange::review_diff()` shows the document change while disabling external diff commands and text conversion. An equivalent shell command is `git --git-dir <artifact> diff --no-ext-diff --no-textconv --text <revision> <ref>`. The linked worktree has the reviewed destination as its only uncommitted change. Review and commit from `PreparedChange::worktree()`; the source checkout stays unchanged, so an editor's save there is never replaced. The accepted worktree belongs to the user. `discard` removes the private artifact but never edits or deletes that worktree; the user removes it separately after handling its changes. Rejecting before acceptance creates no worktree. Only a normal signed commit and PR can share the accepted document.

Issue #584 connects this boundary to the memory UI after the current settings and context changes land. Until then, this crate is exercised by its isolated behavior tests and is not exposed in Sail.
